## Changes made

### 1. `#how` — "Cara Pelanggan Order" — Styled step image placeholders

**Before:** Each `.step-img` div was empty (an empty box with `background:var(--ice)` and `border:1.5px dashed var(--line)`). The `<img>` tags were commented out. On the live page, four dashed gray squares appeared above each step card, clearly communicating "unfinished."

**Design direction:** Retain the existing 4-column grid and `→` / `↓` connecting arrows (already implemented via CSS `::after` — no change needed). Fill each empty image slot with a colored icon placeholder using existing design tokens. Per-step accent colors maintain visual variety while staying within the brand palette.

**Key decisions:**
- `position:relative` added to `.step-img` to create a positioning context for the absolute-fill placeholder.
- `.step-img-placeholder` is `position:absolute;inset:0` — fills the entire square container, overriding the `var(--ice)` background visually. The dashed border is covered by the placeholder background.
- Each step gets a distinct accent color from the existing token set:
  - Step 1 (Sit) — Amber `#FFF7ED` / `#D97706` (person icon)
  - Step 2 (Scan QR) — Blue `var(--blue-50)` / `var(--blue)` (QR icon)
  - Step 3 (Order) — Mint `var(--mint)` / `#059669` (list+check icon)
  - Step 4 (Pay) — Purple `#F5F3FF` / `#7C3AED` (coin/currency icon)
- Each `.step-img` now has `id="how-img-N"` and `data-asset-id="HOW-N"` so it maps directly to ASSETS.md slots.
- The `::after` connecting arrows on desktop (`→`) and mobile (`↓`) were already correctly implemented — no changes.

**Responsive behavior:** The 4-column grid already collapses to 1 column on mobile (`max-width:760px`). The placeholders fill their container at any width. At `max-width:400px` the aspect ratio changes to `4/3` — placeholders adapt automatically.

**To swap in a real photo:** Remove the `.step-img-placeholder` div and add `<img src="step-N.webp" alt="..." loading="lazy">` inside the same `.step-img` div. The existing `.step-img img{width:100%;height:100%;object-fit:contain}` CSS handles sizing.

**Needs manual browser check:** Verify the colored icon placeholders render correctly and are visually distinct from one another. Check that the `→` / `↓` arrows between cards are visible at both desktop and mobile breakpoints.

### 2. `#founders` — "Tim Kami / Our Team" — Brand-gradient founder avatars

**Before:** `.founder-photo` had `background:linear-gradient(135deg,#E2E6EE 0%,#CBD0DA 100%)` (flat gray) and `color:var(--muted)` — the "F1"/"F2" initials appeared in gray-on-gray. Visually it looked like a browser default or an error state, not an intentional design element.

**Design direction:** Use the existing `--grad-brand` (electric blue → cyan gradient) already present in buttons and logo mark. White initials on this background look intentional and on-brand. This is a minimal change (2 CSS property values) with high visual impact.

**Key decisions:**
- `background:var(--grad-brand)` — matches the logo mark (`.mark` CSS in nav) exactly. Consistent with brand.
- `color:#fff` — white initials read clearly on the gradient.
- No font/size/layout changes — only the background and foreground color.
- This reads as "branded avatar" until a real photo is provided, rather than "missing image."

**To add a real founder photo:** Add `<img src="founder1.webp" alt="[Name]">` inside `.founder-photo` and add one CSS rule:
```css
.founder-photo img { width:100%; height:100%; object-fit:cover; border-radius:50%; }
```
The initials ("F1"/"F2") text content of the div will be hidden behind the image.

**Needs manual browser check:** Verify the gradient renders correctly on the 120×120 px circle at both retina and 1× displays.

## `#owner` — NOT changed (content-only issue)

**Observation:** Each `.owner-slide` has a `.owner-slide-tag` with `data-i18n="owner.ph"`. The current `owner.ph` value in `illustrations.js` is `"[[TODO: foto owner/suasana restoran — ganti sebelum launch]]"` (ID) / `"[[TODO: owner/restaurant photo — replace before launch]]"` (EN). This TODO text is visible to site visitors as a badge at the bottom of each owner carousel slide.

**Why not changed here:** Editing `owner.ph` is a content/copy decision (tracked in PROGRESS.md "Content TODOs"). The DSGN pass must not change copy or break `data-i18n` bindings.

**Recommended fix (owner action):** Either:
1. Update `owner.ph` (ID & EN) in `illustrations.js` to a short, neutral label such as `"Suasana restoran"` / `"Restaurant setting"`, then replace with a real photo label when available; OR
2. Remove the three `.owner-slide-tag` elements from `#ownerSlides` in `index.html` entirely until a real photo/label is ready.
